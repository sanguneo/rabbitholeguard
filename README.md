# 🕳️ rabbitholeguard

> **AI 코딩 에이전트의 목표 이탈·무한 루프·과잉 검증을 막고 원래 작업으로 복귀시키는 표준 스킬**  
> *A goal-recovery skill with an optional execution guard for OmO / Senpi.*

## 💡 왜 필요한가?

AI 코딩 에이전트에게 복잡하거나 긴 작업을 맡기면 흔히 이런 문제(**삼천포 / Rabbit Hole**)가 발생합니다:

1. **맥락 압축 뒤 목표 상실**: 대화가 길어져 세션이 압축되면 초기 목표를 잊고 엉뚱한 이전 작업이나 곁가지로 샙니다.
2. **근거 없는 무한 재실행**: 코드나 환경이 하나도 바뀌지 않았는데 같은 테스트나 검증 명령을 수없이 반복하며 토큰을 태웁니다.
3. **실패한 방법 왕복 (A ↔ B)**: A 방법이 실패해서 B로 바꿨다가, B도 실패하니 다시 A로 돌아가는 핑퐁 루프를 돕니다.
4. **환경 문제를 코드로 풀기**: 패키지 미설치, 포트 점유, 꺼진 서버 같은 환경 문제를 정상적인 소스 코드를 마구 뜯어고치며 해결하려 듭니다.
5. **목표 임의 축소 / 허위 완료**: 테스트를 삭제하거나 skip하고, 단언문을 약화해 억지로 "완료되었습니다"라고 선언합니다.

`rabbitholeguard`는 [anti-samcheonpo](https://github.com/JinHo-von-Choi/anti-samcheonpo)의 핵심 원칙(작업 계약, 목표 앵커, 반복 방지, 실패 인수인계)을 별도 데몬이나 무거운 런타임 설치 없이 **단일 스킬 규격**으로 압축하여 에이전트가 스스로 탈출할 수 있도록 설계된 가드레일입니다.

두 가지 방식 중 선택할 수 있습니다.

| 방식 | 기본 상태 | 역할 |
|---|---|---|
| [스킬](SKILL.md) | 기본 설치 대상 | 목표 복귀를 위한 행동 지침. 실행을 강제로 막지는 않습니다. |
| [OmO 선택형 훅](docs/optional-hook.md) | 별도 설치, 매 세션 OFF | 사용자가 등록한 동일 bash 검증 명령의 반복 실행을 경고 후 차단합니다. |

## 📦 설치: 에이전트에게 그냥 맡기세요

사용자가 복잡한 터미널 명령을 칠 필요가 없습니다. 저장소 링크나 폴더를 주고 에이전트에게 한 문장만 말하세요:

### 1. 설치 요청
```text
https://github.com/sanguneo/rabbitholeguard 저장소의 SKILL.md를 읽고 rabbitholeguard를 전역 스킬로 설치해줘.
```
*또는 로컬 클론 폴더에서:*
```text
이 폴더의 README.md와 SKILL.md를 읽고 rabbitholeguard를 다른 전역 스킬처럼 설치해줘.
```

에이전트가 알아서 사용자 홈의 전역 스킬 경로(`~/.agents/skills/rabbitholeguard/SKILL.md`)에 설치하고 완료를 보고합니다.  
설치 후 **새 세션**에서 스킬 목록을 확인하세요. 스킬의 자동 선택과 준수는 모델 동작에 달려 있습니다.

### 2. 제거 요청
```text
rabbitholeguard 스킬 제거해줘.
```
에이전트가 다른 스킬이나 원본 저장소를 건드리지 않고 설치본만 깔끔하게 정리합니다.

별도로 설치한 훅도 지우려면 “rabbitholeguard 스킬과 차단 훅 모두 제거해줘”라고 요청하세요. 스킬만 제거하면 훅은 남습니다.

## 🛡️ 핵심 방어 장치 (Key Mechanisms)

| 장치 | 에이전트 행동 규칙 |
|---|---|
| **1. 목표·범위 고정** | 작업 시작 시 최신 요청에서 목표 한 문장, 허용 범위, 완료 조건을 명확히 복원하고 임의로 변경하지 않습니다. |
| **2. 행동-목표 대조** | 도구를 쓰거나 단계를 바꿀 때 지금 하려는 일이 남은 완료 조건에 직접 필요한지 확인합니다. 무관한 확장은 중단합니다. |
| **3. 압축 후 목표 앵커** | 맥락 압축이나 세션 인수인계 직후 최신 목표와 남은 완료 조건을 다시 확인하여 이전 목표로 회귀하지 않습니다. |
| **4. 무근거 반복 금지** | 입력, 코드, 환경이 그대로라면 동일한 검색, 테스트, 파일 검증을 다시 돌리지 않습니다. |
| **5. 실패한 접근 기억** | 실패한 방법과 그 원인 가설을 기록합니다. 실패한 두 상태 사이를 왕복하지 않고 구조적으로 다른 제3의 접근을 택합니다. |
| **6. 환경 vs 코드 분리** | 의존성 미설치, 권한, 포트 점유 등의 문제를 소스 코드 수정으로 우회하지 않고 필요한 외부 조치를 사용자에게 명시합니다. |
| **7. 탐색-구현 균형** | 구현 요청에서 산출물 없이 읽기·검색만 길어지면 탐색을 멈추고 최소 구현이나 질문으로 전환합니다. |
| **8. 완료 기준 변조 금지** | 테스트 삭제, assertion 약화, 예외 삼키기 등으로 거짓 완료를 만들지 않습니다. 결과는 관측된 사실로만 말합니다. |
| **9. 정지 및 인수인계** | 진척 없이 막히면 무의미한 재시도를 멈추고 [목표 / 완료된 것 / 실패한 접근 / 막힌 원인 / 다음 행동]을 요약해 인수인계합니다. |

## 🚀 사용 방법

### 스킬 선택 조건
다음 상황을 스킬 설명의 선택 조건으로 제공합니다. 항상 자동 호출되는 것은 아닙니다:
- 사용자가 *"삼천포로 빠지지 마"*, *"원래 시킨 일 해"*, *"왜 같은 걸 계속 반복해?"* 라고 지적할 때
- 동일 명령이나 테스트가 변경 없이 반복될 때
- 맥락 압축 후 방향을 잃었을 때

### 직접 호출
작업이 헛돌거나 복귀가 필요할 때 언제든 명령하세요:
```text
rabbitholeguard로 원래 목표와 남은 완료 조건 확인하고 바로 복귀해줘.
```

## 선택 사항: 실행 전 차단 훅 (OmO / Senpi)

**스킬 단독 설치가 기본입니다.** 훅은 별도 요청으로 설치하며 설치 후에도 매 세션 기본 OFF입니다. Claude Code·Codex·OpenCode의 훅 어댑터는 포함하지 않습니다.

상세한 설치·업데이트·제거 절차와 문제 해결은 [선택형 훅 가이드](docs/optional-hook.md)를 참고하세요.

에이전트에게 설치를 맡기세요:

```text
rabbitholeguard의 OmO 선택형 차단 훅도 설치해줘. 스킬은 유지해줘.
```

설치하는 에이전트는 이 저장소의 `extensions/rabbitholeguard/index.ts`를 현재 OmO가 사용하는 에이전트 설정 디렉터리의 `extensions/rabbitholeguard/index.ts`에 설치합니다. 설정 디렉터리는 OmO의 `getAgentDir()` 또는 실제 실행 설정으로 확인해야 합니다. Senpi 기본 경로는 `~/.senpi/agent`이지만 OmO 설정에 따라 달라질 수 있으므로 고정 경로를 추측하지 않습니다. 기존 파일이 다르면 사용자 수정 여부를 확인합니다. 다른 확장·설정은 변경하지 않습니다.

새 세션 또는 `/reload` 후, **사용자가** 다음 명령으로 선택합니다. 일반 대화로 켜 달라고 하는 것만으로 켜지지 않으며 모델용 제어 도구는 등록하지 않습니다.

```text
/rabbitholeguard watch bun test
/rabbitholeguard status
/rabbitholeguard off
```

`watch` 뒤에는 감시할 **정확한 bash 명령**을 넣습니다. `bun test`와 `bun test tests/auth.test.ts`는 다른 명령입니다.

| 명령 | 동작 |
|---|---|
| `/rabbitholeguard watch <명령>` | 해당 명령을 감시 대상으로 등록하고 ON |
| `/rabbitholeguard on` / `off` | 등록한 명령에 대한 차단 활성화 / 해제. 감시 명령을 자동 등록하지 않음 |
| `/rabbitholeguard status` | 현재 상태 확인 |
| `/rabbitholeguard reset` | 반복 기록 초기화 |
| `/rabbitholeguard allow-once` | 다음 차단 대상 호출 한 번 허용 |

감시 명령이 변경 없이 두 번 완료되면 실제 결과에 경고를 덧붙이고, 다음 동일 실행을 `tool_call`에서 거부합니다. 실행 결과를 조작해 성공으로 바꾸지는 않습니다. 관측된 수정이나 환경 변경 가능성이 있는 다른 셸 실행, 새 사용자 요청이 있으면 반복 기록을 무효화합니다.

성공·실패 결과 모두 횟수에 포함됩니다. `/reload`와 세션 전환 후에는 OFF로 돌아가며, `watch`로 추가한 명령도 다시 등록해야 합니다. `off`는 해당 세션의 차단만 끄고 확장 파일을 제거하지 않습니다.

**확인 가능한 범위:** 확장 이벤트에 직접 나타나는 도구 호출만 다룹니다. `eval` 안의 중첩 실행, 외부 프로세스의 파일 변경, 다른 세션, 백그라운드 실행의 최종 결과를 완전히 추적하지 않습니다. 명령 글자를 바꾸면 동일 실행으로 보지 않으며 보안 격리 장치는 아닙니다. 목표 이탈 전체를 기계적으로 판정하는 대신, 사용자가 지정한 반복 검증의 낭비만 차단합니다.

제거도 에이전트에게 맡길 수 있습니다:

```text
rabbitholeguard의 차단 훅만 제거해줘. 스킬은 남겨줘.
```

해당 확장 파일만 제거하고 빈 폴더만 정리합니다. 이미 실행 중인 세션에서는 `/rabbitholeguard off` 또는 `/reload`가 필요합니다.

개발 검증: `bun test` (별도 패키지 설치 없이 Bun 필요).

## 🤖 에이전트 자가 설치 규격 (For Agents)

에이전트가 이 패키지의 설치를 요청받았을 때 따르는 규칙:
1. 이 패키지의 `SKILL.md`를 읽고 `name: rabbitholeguard`임을 확인합니다.
2. 사용자 홈 디렉터리의 `~/.agents/skills/rabbitholeguard/SKILL.md`에 복사합니다.
3. 기존에 동일한 파일이 있으면 유지하고, 다른 내용이 있을 때는 임의로 덮어쓰지 않고 확인합니다.
4. 사용자가 직접 셸 명령을 실행할 필요 없이 에이전트가 작업을 완결하고 보고합니다.
