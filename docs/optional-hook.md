# OmO 선택형 차단 훅

[README로 돌아가기](../README.md) · [구현](../extensions/rabbitholeguard/index.ts) · [테스트](../tests/extension.test.ts)

스킬은 목표 복귀를 위한 행동 지침이고, 이 확장은 사용자가 지정한 동일 bash 검증 명령의 반복을 실행 전에 차단합니다. 둘은 별도 설치 대상입니다. 스킬만 설치해도 기존 방식으로 사용할 수 있습니다.

## 설치·업데이트를 맡기기

에이전트에게 저장소 URL과 함께 요청하세요.

```text
https://github.com/sanguneo/rabbitholeguard
README와 docs/optional-hook.md를 읽고 OmO용 선택형 차단 훅을 설치해줘.
기존 스킬은 유지해줘.
```

설치하는 에이전트가 수행할 일:

1. 원본 `extensions/rabbitholeguard/index.ts`를 읽습니다.
2. 현재 OmO가 사용하는 에이전트 설정 디렉터리를 `getAgentDir()` 또는 실제 실행 설정으로 확인합니다. Senpi 기본 경로는 `~/.senpi/agent`이지만 OmO의 경로는 설정에 따라 다를 수 있습니다.
3. 확인한 디렉터리의 `extensions/rabbitholeguard/index.ts`에 원본을 설치합니다. 다른 확장·설정·AGENTS.md는 수정하지 않습니다. 동일한 설치본은 그대로 두고, 내용이 다르면 사용자 수정 여부를 확인합니다.
4. 새 세션 또는 `/reload` 뒤 `/rabbitholeguard status`로 로드 여부와 OFF 상태를 확인하도록 안내합니다. 설치만으로 활성화하지 않습니다.

별도 npm 패키지나 데몬은 필요 없습니다. OmO/Senpi가 TypeScript 확장을 로드합니다. 현재 어댑터는 OmO/Senpi용이며 다른 에이전트의 훅 규격은 구현하지 않았습니다.

업데이트도 “이 저장소의 선택형 훅을 업데이트해줘”라고 맡깁니다. 확장 파일을 갱신한 뒤 새 세션이나 `/reload`에서 다시 로드해야 합니다.

## 세션에서 사용하기

아래 제어 명령은 사용자가 입력합니다. 일반 대화로 활성화를 요청하는 것과 다르며, 모델용 제어 도구는 없습니다.

```text
/rabbitholeguard watch bun test
/rabbitholeguard status
```

`watch`는 정확한 명령을 등록하고 활성화합니다. 최대 128개, 명령당 8192자까지 등록할 수 있습니다. 앞뒤 공백만 제거하고 명령 내부의 공백·따옴표는 보존합니다. `bun test`와 `bun test tests/auth.test.ts`는 서로 다른 대상입니다. 임의의 셸 명령을 자동으로 검증 명령이라고 추정하지 않습니다.

| 명령 | 상태 변화 |
|---|---|
| `watch <명령>` | 대상 추가, ON, 반복 기록 초기화 |
| `on` | ON, 반복 기록 초기화. 기존 등록 대상은 유지 |
| `off` | OFF, 반복 기록 초기화. 기존 등록 대상은 유지 |
| `status` 또는 인자 없음 | 상태·등록 대상 수·완료 기록 수·이번만 허용 여부 표시 |
| `reset` | ON/OFF와 등록 대상은 유지하고 반복 기록 초기화 |
| `allow-once` | 다음 차단 대상 실행 한 번 허용. 일반 실행은 이 허용을 소비하지 않음 |

모든 명령은 `/rabbitholeguard` 뒤에 붙입니다. 예를 들어 `/rabbitholeguard allow-once`입니다.

## 경고와 차단

감시 중인 명령의 실행 결과가 순서대로 도착하고, 사이에 기록을 무효화하는 이벤트가 없다고 가정하면:

1. 첫 완료: 실제 결과를 그대로 전달합니다.
2. 두 번째 완료: 실제 결과에 반복 경고를 덧붙입니다.
3. 세 번째 실행 요청: 실행 전에 이유를 반환하며 차단합니다.

성공·실패 결과 모두 횟수에 포함됩니다. 경고는 실제 출력에 추가되며 기존 오류 상태나 종료 코드가 성공으로 바뀌지 않습니다. 실행 전에 이미 허용된 병렬 호출은 이후 도착한 결과만으로 취소하지 않습니다.

실제로 관련 코드나 환경을 고쳤으면 다시 검증할 수 있습니다. 외부에서 바뀌어 훅이 관측하지 못한 경우에는 사용자가 `reset` 또는 `allow-once`를 선택할 수 있습니다.

반복 기록은 성공한 `write`·`edit`·`apply_patch`, 감시 대상이 아닌 bash 실행, 새 사용자 입력에서 초기화됩니다. 읽기만 하거나 실패한 수정은 초기화하지 않습니다. 새 세션·세션 전환·재로드·종료에서는 OFF로 돌아가며 `watch`로 추가한 대상도 사라집니다.

## 끄기와 제거

현재 세션에서만 끄려면:

```text
/rabbitholeguard off
```

설치 파일까지 제거하려면 에이전트에게 맡깁니다:

```text
rabbitholeguard의 차단 훅만 제거해줘. 스킬은 남겨줘.
```

에이전트는 실제 설정 디렉터리의 해당 확장 파일만 제거하고, 비어 있는 폴더만 정리합니다. 추가 파일·배포 원본·스킬은 보존합니다. 이미 로드된 세션에는 제거만으로 반영되지 않으므로 `off`, `/reload` 또는 새 세션이 필요합니다.

스킬과 훅 모두 제거하려면 “rabbitholeguard 스킬과 차단 훅을 모두 제거해줘”라고 요청하세요.

## 동작하지 않을 때

- **명령을 찾을 수 없음:** 파일이 현재 OmO 설정 디렉터리에 설치됐는지 확인하고 새 세션 또는 `/reload`로 로드합니다.
- **ON인데 차단하지 않음:** `on`은 명령을 등록하지 않습니다. `watch <정확한 명령>`을 사용하고, 다른 셸 실행이나 새 요청으로 기록이 초기화됐는지 확인합니다.
- **재로드 뒤 꺼짐:** 의도된 동작입니다. 감시할 명령을 다시 `watch`로 등록합니다.
- **환경을 고쳤는데 차단됨:** 외부 변경은 관측하지 못할 수 있습니다. `reset` 또는 `allow-once`로 필요한 재검증을 허용합니다.

## 관측 범위와 검증

직접 도구 이벤트에 나타나는 bash 호출과 완료 결과만 세고, 백그라운드 핸들 `bash_id`가 있는 결과는 완료로 세지 않습니다. `eval` 내부의 중첩 실행·외부 파일 변경·다른 세션·비동기 작업의 최종 결과는 완전히 감시하지 않습니다. 명령을 다르게 쓰거나 다른 셸을 거치면 동일 실행으로 보지 않습니다.

파일 내용 지문, 보호 경로, 목표 의미 판정, 예산 제한은 이 훅의 기능이 아닙니다. 보안 격리나 모든 삼천포 방지를 보장하지 않습니다.

개발 검증은 저장소에서 `bun test`로 실행합니다. 기본 OFF, 경고 후 차단, 이번만 허용, 해제, 변경 후 기록 무효화, 세션 초기화, 병렬 호출을 테스트합니다. 실제 Senpi 확장 로더·ExtensionRunner와 셸 실행에서도 핵심 차단·해제 동작을 확인했습니다.
